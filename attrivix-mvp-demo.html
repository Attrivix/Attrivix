Households: one spouse calls, the other books

185 cases of this kind in the demo data

3,475 of 3,475 households rebuilt from name, address, and phone
185 of 185 calls linked to the other spouse's loan
$15.7M in borrowing spouse loans behind those calls
How this was built and where it stops: The core's own household ID was left out. Attrivix infers each household from name, address, and phone, then links a touch to another household member's funded loan when the touch falls in the 14 days before that loan's application. The demo addresses are clean, so the first number is the easy one. On a copy with 57% of addresses and 6% of surnames degraded (typos, abbreviations, stray unit numbers, hyphenated names), the same rules kept 100% precision and found 96.5% of household pairs. The 14 day window was set with these planted cases in view, so a real credit union will need its own check. 150 more touches from a household member land in the same window. The answer key does not label them, so they are not counted here.

After matching: tokens only

Matching runs on the original data first, because fuzzy matching cannot run on hashed values

56,605 text values scanned in the tokenized tables
0 original member IDs, emails, phones, or names found

Once households and links are final, member and household IDs become keyed tokens (HMAC-SHA256), and names, emails, phones, and addresses are dropped. The same scan finds a value we plant on purpose, so a result of zero means something.

Where this stands today: the tokenization code runs on the demo dataset with a demo key file. Holding the key in Azure Key Vault inside the credit union's tenant, and running the matching step in a confidential computing enclave, are not built or verified yet.

Review loop: questions get asked once

Matches the engine will not decide alone go to a person, and the answer is kept

3 touches waiting for a reviewer today, 4,493 of 4,496 resolved
4,496 of 4,496 resolved after review, 0 wrong
16 to 0 household pairs in the queue after review

On the messy address copy, a reviewer confirming 16 near-miss household pairs lifted household recall from 96.5% to 97.6% with precision held at 100%. A saved decision applies on every later run, so the same pair is not asked about again. A touch decision settles only that touch. Two of the queued touches carry the same email and the same name, yet belong to two different people, so a decision is never turned into a rule for other touches. A decision that names someone the evidence never pointed to is refused.

Where this stands today: the reviewer in this demo is simulated from the answer key. The queue and the decisions are files. Sending each question to the loan officer on the file, and escalating when that person leaves, is not built.
