Five source systems

Core, loan system, marketing, call center, and website. Each one keeps its own member ID and its own version of a member's email, phone, and household.

Layer 1
Ingestion

Target design

Connectors read from the five systems by API or SFTP. Phase 1 is read only. The demo dataset was generated as files, so connectors are not part of what the demo runs.

Layer 2
Resolution and logic

Shown on demo data

Matching people across emails and phones, building households from name, address, and phone, linking a spouse's call to the other spouse's loan, tokenizing after matching, and the U-shaped attribution all run on the demo dataset. Key storage in Azure Key Vault and the secure enclave are not built yet.

Layer 3
Output

Tables shown

Attribution tables exist for the demo dataset. A semantic model that Power BI and Copilot can query in plain language is the target design.
