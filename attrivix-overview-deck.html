The problem

No system sees the whole path from first touch to funded loan.

System of record for all member data and funded loans

03

05

Visits, clicks, and application starts, tracked in Google Analytics

UTM codes and tools like SavvyMoney can tie some funded loans back to a campaign in a single system like an LOS, and that is genuinely useful. Many still go unmatched, because member data can vary and the same member can show up under a different email, phone, or household in each system. Today those systems do not see each other’s data, so the credit union has no full 360 degree view.

Source: Cornerstone Advisors, The Marketing ROI Gap in Banking, 2026 survey of 126 bank and credit union executives, commissioned by Fintel Connect. No institution said it could reliably trace results to marketing for every outcome tested.

How it works

Three layers, all inside the credit union’s tenant.

Layer 1

Ingestion

Connectors pull from the core, loan system, marketing platform, call center, and website by API or SFTP.

Layer 2

Resolution and logic

Matches people and households across systems, then applies attribution rules that tie each touch to a funded loan.

Layer 3

Output

Tables and a semantic model that Power BI and Copilot can query in plain language.

Attrivix

Resolution layer

The resolution layer ties every system to one person and one household.

01

Ingest each system’s IDs

The member ID or GUID from every source becomes a link to one identity.

02

Match members and households

Matching runs inside the credit union’s tenant on the original data. Attrivix builds households from name, address, and phone, since most cores supply no household ID. A spouse’s call links to the other spouse’s loan.

03

Learn from confirmed matches

Unclear matches go to a reviewer, and each answer is kept so the same question is not asked twice.

04

Tokenize after matching

Once matching is done, names, emails, and phones become tokens, and only the tokens move forward.

Where this stands today: on the demo dataset, matching resolves 99.9% of touches to a member, rebuilds all 3,475 households, and links 185 of 185 spouse calls to the other spouse’s loan. Tokenization runs after matching, using a demo key. Review answers are saved and reused, with a simulated reviewer for now. Key storage in Azure Key Vault, the secure enclave, and routing questions to the right person are not built yet.
